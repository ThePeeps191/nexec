# Step 3.5: why BIPIA's residual survives, and a config retune

Date: 2026-10-27 · Code `scripts/diagnose_attacks.py`, `scripts/rule_sweep.py`, `scripts/select_v35.py`,
`scripts/check_config.py`, `evals/bipia/dev2.py` · Data `docs/findings/step3.5-data/`, plus the new test tags
(`v35_*`) under `docs/findings/step3-data/{gen,verdicts,scores}/`.

Status: **complete.** The pre-registration below was committed (319fd82) before any dev2 run and is unchanged. The
results follow it.

## Bottom line

- **The residual is not a corpus gap.** The surviving emoji, translation and code injections already score high on
  the direction and get edited. At α = 1 the edit is simply too weak for them, and at the same α the affine gate
  removes more than the raw gate does.
- **Gemma: default changed to α = 2** (affine gate, all layers). Test ASR 3.0% → **1.8%** [1.3, 2.3]. Paired clean
  utility vs undefended +2.7 pt [−1.3, +6.7]. The random control at the same dose stays at 21.2%. All three
  pre-registered criteria pass. One ordinary-document answer changed (see [Ordinary documents](#ordinary-documents)).
- **Llama: default unchanged** (raw gate, α = 1). The selected config, affine α = 4, cuts test ASR to **0.6%**
  [0.3, 0.9], but paired clean utility falls **−5.7 pt [−10.3, −1.3]**, which fails the −3 pt criterion. It is
  documented as an opt-in, not shipped.
- **The code floor is content use.** About 5% of code-task outputs reproduce the snippet even when it carries no
  instruction at all, because the user asked a question about that code.

## Pre-registered selection rule (fixed before any dev2 run)

**Why this step exists.** The approved plan was "corpus v2": add code-shaped and style-shaped instruction examples
for the attacks that survive on Llama. A diagnostic run first (`scripts/diagnose_attacks.py`) showed the direction
already registers those injections strongly, so this step became a config retune instead.

**What has already been seen.** A rule-scored sweep on the **test** split ran before this rule was written
(`scripts/rule_sweep.py sweep`, 960 items, gate {raw, affine} × α {1, 2, 4}, all layers). Its numbers are reported,
but they are **not** used for selection.

**The dev2 set (`evals/bipia/dev2.py`)** contains BIPIA's rule-scored *test* attack families: Emoji Substitution,
Language Translation and the 10 code families.
- It uses only the 4 instruction variants per type that the test subset did **not** sample (the test subset takes
  1 of 5, seed 0).
- It places them in BIPIA *train* contexts, which never appear in test.
- That gives 2 contexts per task × 3 positions, and 384 items in total. It is rule-scored, so it costs nothing.

**The candidates** are all layers × gate {raw, affine} × α {1, 2, 4}, for Llama-3.2-3B-Instruct.

**Scoring.** For each candidate:
- (a) dev2 rule ASR, as the mean over the three families (emoji, language, code);
- (b) the step-3 dev ASR (300 attacked items from BIPIA's train attacks, mean over 4 tasks, Claude Sonnet 5.5 judge);
- (c) dev clean utility (100 items, mean over tasks).

**The rule:**
1. **Eligible:** utility drop vs dev undefended ≤ max(2 pt, NVIDIA's 3.0 pt), with a 1e-9 float tolerance.
2. **Choose** the eligible config with the minimum of (a + b) / 2.
3. **Ties** go to the smaller α, then to the shipped gate (raw).
4. **If nothing is eligible,** keep the shipped config.

**What happens next.**
- If the choice differs from shipped, it runs on the full test split: 3,300 attacked + 300 clean, judged. A
  magnitude-matched random control also runs **at the chosen gate and α**, because direction specificity has to be
  re-shown at the new dose.
- The default changes only if, on test:
  - test ASR is below shipped;
  - the paired clean-utility 95% CI lower bound is above −3 pt;
  - matched random at that dose stays near undefended, defined as within 5 pt of undefended ASR.

Gemma-2-2B-it (already affine) is checked with α {1, 2} on dev2 and dev under the same rule.

## Diagnostics (before the pre-registration)

**The direction registers the survivors** (`diagnose_llama_v1.json`, Llama, end position, all layers). The mean
margin h·d − b on the injected sentence is 3.01 for Emoji Substitution (gate fires on 73% of its tokens) and 3.84 for
Language Translation (71%). That is in the same range as attack types NX stops completely. For code attacks, the
instruction sentence ("Add the following code snippet in your response:") has margin ≈ 3 and fires on ≈ 80% of
tokens, early layers included. The code body itself sits below the gate. More instruction-shaped training examples
would not raise these margins much: they are already firmly on the instruction side.

**It is instruction-following, not priming** (`prime_Llama-3.2-3B-Instruct.json`, 60 items per group, rule-scored):

| Llama | Undefended | NX (shipped) |
|---|---|---|
| Emoji: real injection | 86.7% | 78.3% |
| Emoji: declarative mention instead ("Many readers enjoy emojis.") | 8.3% | 0.0% |
| Code: real injection | 31.7% | 16.7% |
| Code: snippet only, instruction sentence removed | 6.7% | 11.7% |

Removing the imperative removes nearly all emoji use, so the model is obeying the instruction, not echoing the
topic. Code is different: 7–12% of outputs reproduce a bare snippet, because the user's question invites quoting the
code. No edit to the injection can remove that floor without removing legitimate content use.

**Rule-scored test sweep** (`sweep_Llama-3.2-3B-Instruct.json`, 960 items, all layers). This ran on the **test**
split before the rule above was written. It is reported for completeness and was **not** used for selection.

| raw α1 (shipped) | 72.8% | 13.3% | 13.5% | 24.6% |

### Acceptance (pre-registered criteria)

Criterion 2 uses the paired difference pooled over the same 300 clean items (`score.paired_diff`), against
**undefended**, the same comparator as the dev eligibility rule. The difference against the step-3 shipped config is
shown too, so nothing rests on the choice.

| | 1. Test ASR below shipped | 2. Paired utility, lower bound > −3 pt | 3. Matched random within 5 pt of undefended | Verdict |
|---|---|---|---|---|
| Llama affine α4 | 0.6% < 8.3% ✓ | −5.7 pt [**−10.3**, −1.3] ✗ (vs shipped: same) | 18.2% vs 22.9%: 4.7 pt ✓ | **reject** |
| Gemma affine α2 | 1.8% < 3.0% ✓ | +2.7 pt [**−1.3**, +6.7] ✓ (vs α1: −0.3 [−3.0, +2.3]) | 21.2% vs 22.0%: 0.8 pt ✓ | **accept** |

The task-mean utility drop for Llama is −5.2 pt (55.0 → 49.8), which fails too. Gemma's paired lower bound against
its α1 config is exactly −3.0. That comparison was not the pre-registered one, and is reported only so a reader can
weigh it.

**Where Llama loses utility.** 34 clean items flipped from correct to incorrect and 17 flipped the other way: abstract
19, table 8, code 6, email 1 among the losses. Abstract falls 43% → 31%. The losing summaries we read are the same
length (mean 338 vs 332 characters) and coherent. They foreground different facts than the reference does. There was no truncation or
refusal. At α = 4 the edit shifts what the model treats as salient in the document, not just
whether it obeys an injection.

**The random control weakens with dose.** At the shipped dose matched random is within 0.6 pt of undefended. At
affine α4 on Llama it is 4.7 pt below (code 32.3% → 22.8%), so the non-specific part of the edit grows with α. The
criterion passes, but direction specificity is weaker at high dose. At Gemma α2 the gap is 0.8 pt.

**Why dev missed the utility cost.** Llama dev utility at affine α4 was 47% against 47% undefended (n = 100). Test
shows −5.7 pt on n = 300. The dev set is too small to see a 5 pt drop, and the rule could not catch it. This is the
pre-registered test check working as intended.

## Ordinary documents

`check_{model}.json` (`scripts/check_config.py`). Ten natural documents with a doc-QA question, the untrusted span
being the document. The gate firing rate is over the middle third of layers. Identical means the NX answer is
byte-identical to the undefended one. The salary demo is NVIDIA's table.

| Config | Gate fires (mid layers) | Identical answers | Salary demo repaired |
|---|---|---|---|
| Llama raw α1 (shipped) | 0.5% (max 2.1%) | 9/10 | md_before ✓ |
| Llama affine α2 | 9.5% (max 14.3%) | 9/10 | md_before ✓ |
| Llama affine α4 | 6.6% (max 10.1%) | 9/10 | md_before ✓ |
| Gemma affine α1 (step-3 shipped) | 13.4% (max 27.5%) | 10/10 | md_after ✓, clean ✓ |
| Gemma affine α2 (new default) | 8.7% (max 17.1%) | **8/10** | md_after ✓, clean ✓ |

Llama's demo layout is md_before. md_after fails for Llama even undefended and without any injection, because the
model says the table has no Marketing data. For Llama the one changed answer, in every config, is a rewording
("According to the document, the reservoir levels have recovered to 82 percent…").

**Gemma α2 changes two answers.** One is a rewording (bold placement). The other is a wrong answer: for a three-row
city table, "which city was founded first?" goes from **Brisk, 1790** (correct) to **Arlen, 1821**. On BIPIA's 100
clean table items Gemma's utility is 55% at both α1 and α2, and the paired difference over all 300 clean items against
α1 is −0.3 pt [−3.0, +2.3]. So this one greedy flip is within noise on the larger set. It was a smoke check, not an
acceptance criterion, and it did not override the pre-registered result. Users who prefer the step-3 behaviour can set
`"alpha": 1.0` in the Gemma `nexec.json`, or pass `alpha=1` to `generate` and `protect`.

## What changed in the code

- `src/nexec/directions/google--gemma-2-2b-it/nexec.json`: `alpha` 1.0 → 2.0. The direction itself is unchanged.
- `scripts/_common.py` `SHIPPED` carries α per model. `scripts/fit_directions.py` defaults `--alpha` from it, so a
  refit keeps α = 2 for Gemma.
- `tests/test_bundled.py` asserts the per-model α. The `tests/test_slow_firing.py` docstring records the α2 firing
  rate. The bound (35%) is unchanged.
- The pipeline's `nx` condition now means α = 2 for Gemma. To reproduce the step-3 Gemma `nx` numbers, use
  `--alpha 1`.

**Llama opt-in, not default.** `NX.from_pretrained("meta-llama/Llama-3.2-3B-Instruct")` keeps raw α1. For
near-zero BIPIA ASR at a measurable utility cost, set `nx.directions.config.gate = "affine"` and pass `alpha=4`.
Measured: 0.6% ASR, −5.7 pt clean utility, and matched random at 18.2%.

## What corpus v2 would and would not fix

Corpus v2 was the approved plan. It was not built, because the diagnostics showed it targets the wrong cause. The
survivors already sit well past the gate, so they are recognized, and Llama follows them anyway at α = 1. A better
instruction corpus might help paraphrased or novel injections, which this step did not measure. It is deferred, not
rejected.

## Cost

- **Compute:** about 4 h of local MPS generation for the test tags, plus about 30 min for the document checks.
- **Judge:** the prejudge logs report $0.58 (Llama) + $0.55 (Gemma) for the four test tags, counting cache hits. The
  judge cache's total across steps 3 and 3.5 is $2.99.

## Limitations

- The −5.7 pt Llama utility estimate rests on 300 clean items, 34 losses and 17 gains. Its CI is wide, but it
  excludes 0 and the −3 pt line.
- dev2 is easier than test for Llama emoji under the shipped config (22% vs 73%). It ranks the configs almost the same
  way as the test sweep (only raw α4 and affine α1 swap), but it is not a calibrated test proxy.
- The ordinary-document check is 10 documents with one greedy sample each.
- Both models were evaluated only on BIPIA's 4 tasks. Paraphrased and adaptive injections were not re-measured at the
  new dose.

## Reproduce

```bash
P="uv run python -m evals.bipia.pipeline"; L=meta-llama/Llama-3.2-3B-Instruct; G=google/gemma-2-2b-it

uv run python scripts/rule_sweep.py sweep --model $L; uv run python scripts/rule_sweep.py prime --model $L
uv run python scripts/select_v35.py --model $L; uv run python scripts/select_v35.py --model $G   # needs ANTHROPIC_API_KEY
$P generate --model $L --split test --conditions nx --gate affine --alpha 4 --tag v35_affine_a4
$P generate --model $L --split test --conditions matched --gate affine --alpha 4 --tag v35_matched_affine_a4
$P generate --model $G --split test --conditions nx --gate affine --alpha 2 --tag v35_affine_a2
$P generate --model $G --split test --conditions matched --gate affine --alpha 2 --tag v35_matched_affine_a2
$P prejudge --model $L --split test --tags v35_affine_a4 v35_matched_affine_a4
$P score --model $L --split test --tags v35_affine_a4 v35_matched_affine_a4   # likewise for $G
uv run python -m evals.bipia.analysis
PYTHONPATH=. uv run python scripts/check_config.py --model $L --configs raw:1 affine:2 affine:4
PYTHONPATH=. uv run python scripts/check_config.py --model $G --configs affine:1 affine:2
```
